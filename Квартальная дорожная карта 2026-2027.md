# Квартальная дорожная карта — 2026–2027

> [!abstract] Назначение
> Главный план обучения и развития. Эта заметка определяет **приоритеты кварталов и измеримые результаты**. Подробные темы и задания находятся в отдельных дорожных картах языков и профессий.

## Принципы планирования

- **C++ — основной приоритет.** Не переключаться на следующий язык только потому, что он запланирован календарём.
- **Один главный результат на квартал.** Дополнительные направления не должны мешать основному.
- **Практика важнее количества пройденных уроков.** Каждый квартал должен оставлять проверяемый результат.
- **Не добавлять функции ради количества.** Проект должен решать конкретную задачу.
- **План можно корректировать.** Перенос задачи — нормальная корректировка, а не провал.
- **Не включать спортивное программирование** в эту дорожную карту.
- Zig подключается после устойчивой практики на C++ и Rust.

## Подготовительный квартал — Q4 2026

**Период:** 29 октября — 31 декабря 2026  
**Главная цель:** закрепить фундамент C++ и подготовить базу для дальнейшего изучения ООП и системного программирования.

### Задачи

- [ ] Продолжить тему 2 — классы и инкапсуляция в [[C++]].
- [ ] Закрепить `struct`, `enum`, `enum class`, указатели и динамическую память на практических задачах.
- [ ] Продолжить один выбранный проект, например систему управления заказами.
- [ ] Практиковаться в разбиении кода на логические компоненты.
- [ ] Организовать учебные заметки и связи между дорожными картами в Obsidian.
- [ ] Подготовить план Q1 2027 на основе фактического прогресса.

### Измеримые результаты к 31 декабря

- [ ] Текущая тема C++ завершена по критериям соответствующей учебной карты.
- [ ] Есть хотя бы один проект, который собирается и выполняет заявленные функции.
- [ ] Описаны назначение проекта, его структура и ограничения.
- [ ] Сформирован реалистичный план следующего квартала.

### Критерий завершения

Я могу объяснить устройство проекта, самостоятельно внести изменение и исправить возникшую ошибку без переписывания программы с нуля.

**Ограничение:** не пытаться освоить весь C++ за оставшуюся часть года. Главная задача — закрепить базу и определить точку продолжения.

## Q1 2027 — Современный C++ и инженерная база

**Период:** январь — март 2027  
**Главная цель:** научиться создавать небольшие структурированные и поддерживаемые C++-программы.

### Направления

- [ ] Продвигаться по [[C++]] и закрывать темы в порядке основной дорожной карты.
- [ ] Освоить необходимые темы ООП и управления ресурсами.
- [ ] Научиться разделять код на заголовочные (`.hpp`/`.h`) и исходные (`.cpp`) файлы.
- [ ] Использовать Git для контроля версий.
- [ ] Освоить базовую сборку проекта через CMake.
- [ ] Научиться проверять основные сценарии и ошибки ввода.
- [ ] Завершить один проект с чётко определёнными требованиями.

### Измеримые результаты

- [ ] Завершён один проект на C++.
- [ ] Проект собирается через CMake.
- [ ] Код разделён на логические компоненты.
- [ ] Проверены основные сценарии и некорректный ввод.
- [ ] README описывает назначение, сборку и использование проекта.
- [ ] Я могу объяснить ключевые решения и самостоятельно добавить функцию.

### Критерий завершения

Проект можно собрать по инструкции на чистом рабочем каталоге; его устройство понятно мне самому, а не только компилятору.

**Дополнительно, если остаётся время:** изучить подходящие алгоритмы и контейнеры стандартной библиотеки C++ в соответствии с основной дорожной картой.

## Q2 2027 — Системное программирование

**Период:** апрель — июнь 2027  
**Главная цель:** понять, как программы взаимодействуют с операционной системой, и применить это в проекте.

### Направления

- [ ] Продолжать [[C++]] и закреплять сложные темы через практику.
- [ ] Изучить процессы, файловую систему и системные инструменты Linux.
- [ ] Разобраться с базовыми системными вызовами и взаимодействием с процессами.
- [ ] Освоить инструменты диагностики и отладки в Linux.
- [ ] Выбрать одну системную задачу и реализовать утилиту для её решения.

### Возможные проекты — выбрать один

- Анализатор использования дискового пространства.
- Утилита мониторинга процессов.
- Инструмент пакетной обработки файлов.

### Измеримые результаты

- [ ] Реализована одна системная утилита на C++.
- [ ] Программа использует хотя бы один изученный механизм взаимодействия с ОС.
- [ ] Реализована обработка ошибок.
- [ ] Документированы назначение и ограничения программы.
- [ ] Есть инструкции по сборке и запуску в Linux.
- [ ] Я могу объяснить используемый механизм ОС и причины выбранного решения.

### Критерий завершения

Утилита решает реальную задачу, а я понимаю не только собственный код, но и механизмы ОС, на которые он опирается.

## Q3 2027 — Rust и инженерная практика

**Период:** июль — сентябрь 2027  
**Главная цель:** начать самостоятельную разработку на Rust, используя инженерный опыт, полученный с C++.

> [!warning] Условие перехода
> Rust становится активным дополнительным направлением, если база C++ достаточно устойчива и системный проект не заброшен. Если фундаментальные задачи ещё не закрыты, приоритет остаётся за C++.

### Направления

- [ ] Продвигаться по [[Rust]] согласно отдельной дорожной карте.
- [ ] Изучить синтаксис, структуры, перечисления и обработку ошибок.
- [ ] Разобраться с владением, заимствованием и временем жизни на практике.
- [ ] Создать один небольшой самостоятельный проект на Rust.
- [ ] Сравнить решения одной практической задачи на C++ и Rust.
- [ ] Поддерживать навыки C++ через небольшие исправления и улучшения существующего проекта.

### Измеримые результаты

- [ ] Пройдены основные начальные темы Rust по критериям учебной карты.
- [ ] Реализован небольшой проект на Rust.
- [ ] В проекте используются изученные структуры данных и механизмы обработки ошибок.
- [ ] Я могу объяснить хотя бы несколько случаев, когда правила владения запрещают небезопасную операцию.
- [ ] Подготовлено краткое сравнение одного решения на C++ и Rust.

### Критерий завершения

Я могу самостоятельно написать, собрать и отладить небольшую программу на Rust, объяснить её работу и обосновать использование основных конструкций языка.

**Zig пока не добавлять по умолчанию.** Возвращаться к вопросу о Zig только после устойчивой практики в C++ и Rust.

## Q4 2027 — Собственный продукт и выбор специализации

**Период:** октябрь — декабрь 2027  
**Главная цель:** применить накопленные знания в собственном продукте и выбрать профессиональное направление для дальнейшего развития.

### Направления

- [ ] Выбрать конкретную проблему, которую действительно хочется решить.
- [ ] Определить пользователя, основной сценарий и границы MVP.
- [ ] Реализовать минимальную работающую версию.
- [ ] Добавить сборку, проверки и документацию, необходимые проекту.
- [ ] Изучить инструменты запуска, диагностики и эксплуатации, соответствующие архитектуре проекта.
- [ ] Сравнить профессиональные гипотезы: [[Systems Engineer]], [[Backend Engineer]], [[DevOps Engineer]], [[Product Engineer]].
- [ ] Определить главный профессиональный приоритет на 2028 год.

### Измеримые результаты

- [ ] Сформулирована проблема и определены границы MVP.
- [ ] Реализована работающая основная функция.
- [ ] Есть инструкция по сборке, запуску и проверке.
- [ ] Проект продемонстрирован другому человеку или получена обратная связь, если это возможно.
- [ ] Выбрано основное профессиональное направление и записаны причины выбора.
- [ ] Подготовлен план развития на 2028 год.

### Критерий завершения

Есть работающий MVP, понятные инженерные решения и обоснованный следующий шаг в обучении.

**Важно:** не переключаться на Backend или DevOps только ради выполнения плана. Выбор должен опираться на опыт реальной разработки и то, какие задачи действительно интересны.

## Нагрузка и режим

| Показатель | Ориентир |
|---|---|
| Общее время обучения | 10–14 часов в неделю |
| Практика и проекты | 3–5 часов в неделю внутри общего времени |
| Основные направления одновременно | 1 основное + максимум 1 дополнительное |
| Пересмотр плана | В конце каждого месяца |
| Итоговая оценка | Проверяемый результат, а не количество часов |

Это ориентир, а не обязательная норма на каждый день. При росте учебной нагрузки сокращать объём второстепенных задач, а не сон и отдых.

## Критерии завершения квартала

Квартал оценивается по трём условиям:

1. **Практический результат:** создана программа, утилита или законченная часть проекта.
2. **Понимание:** я могу объяснить устройство решения и самостоятельно изменить код.
3. **Подтверждение:** есть проверяемый результат — репозиторий, тесты, документация или демонстрация.

Если выполнены два условия из трёх, квартал не считается автоматически проваленным. Нужно определить недостающее условие и перенести конкретную задачу в следующий план.

## Итоговая стратегия

**Закрепить C++ → освоить инженерные инструменты → перейти к системному программированию → подключить Rust → создать собственный продукт и выбрать специализацию.**

Zig подключается позднее, когда C++ и Rust уже дают устойчивую практическую базу. Подробные темы, задания и мини-проекты остаются в отдельных дорожных картах; эта заметка управляет приоритетами и результатами по кварталам.
