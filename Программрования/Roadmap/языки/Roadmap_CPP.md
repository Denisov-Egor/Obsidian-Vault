# Roadmap C++ — от основ к C++ Systems Engineer

> Формат: Markdown для Obsidian.  
> Цель: последовательно освоить современный C++ и системное программирование, научиться проектировать, тестировать, отлаживать и собирать реальные программы.  
> Принцип: переходи к следующему этапу после выполнения критериев текущего. Не нужно изучать все темы одновременно.

## Как пользоваться планом

- [ ] Создай заметку для каждой темы или веди конспект прямо в этом файле.
- [ ] Для каждой темы запиши: определение, зачем нужна, правила использования, типичные ошибки и небольшой пример.
- [ ] Практику выполняй самостоятельно. Сначала сформулируй решение и критерии готовности, затем пиши код.
- [ ] Не переходи дальше только потому, что прочитал теорию: нужно уметь объяснить тему и применить её без пошаговой инструкции.
- [ ] Для проектов используй Git и сохраняй понятную историю изменений.
- [ ] Спортивное программирование и Codeforces в этот план не входят.

## Рекомендуемый режим

При занятиях по 2–3 часа в день ориентируйся на качество освоения, а не на жёсткие сроки.

Пример одной сессии:
1. 20–35 минут — теория и заметки.
2. 70–100 минут — практика.
3. 15–25 минут — тестирование, разбор ошибок и рефакторинг.
4. 5–10 минут — запись прогресса и следующего конкретного шага.

# Этап 0. Рабочее окружение и базовый процесс разработки

## Теория
- [ ] Компилятор, препроцессор, компиляция, компоновка и исполняемый файл.
- [ ] Исходные файлы `.cpp`, заголовочные файлы `.h`/`.hpp`, объявления и определения.
- [ ] Основные параметры компилятора: стандарт языка, предупреждения, отладочная информация.
- [ ] Терминал и базовые команды Linux.
- [ ] Git: `status`, `add`, `commit`, `log`, `diff`, ветки и `.gitignore`.
- [ ] Структура небольшого проекта и разделение кода по файлам.
- [ ] Разница между ошибками компиляции, компоновки и ошибками во время выполнения.

## Практика
- [ ] Создай проект с отдельными исходным и заголовочным файлами.
- [ ] Собери его из терминала с включёнными предупреждениями.
- [ ] Намеренно создай по одной ошибке компиляции, компоновки и выполнения; объясни разницу.
- [ ] Создай Git-репозиторий с README и осмысленными коммитами.

## Критерии перехода
- [ ] Можешь собрать программу без IDE.
- [ ] Понимаешь, на каком этапе возникает ошибка.
- [ ] Можешь разделить простую программу на несколько файлов.

# Этап 1. Фундаментальный C++

## Теория
- [ ] Переменные, типы данных, инициализация и область видимости.
- [ ] Целочисленные типы, `float`, `double`, `char`, `bool`.
- [ ] `const`, `constexpr`, литералы и преобразования типов.
- [ ] Арифметические, логические, сравнительные и побитовые операторы.
- [ ] Условия: `if`, `else`, `switch`.
- [ ] Циклы: `for`, `while`, `do-while`, `break`, `continue`.
- [ ] Функции: параметры, возвращаемые значения, перегрузка, прототипы.
- [ ] Передача по значению и базовое понимание стоимости копирования.
- [ ] Массивы, строки `std::string`, базовая работа с `std::getline`.
- [ ] Одномерные и двумерные массивы.
- [ ] Ссылки: `T&` и `const T&`.
- [ ] Указатели: `T*`, `nullptr`, разыменование и арифметика указателей.
- [ ] Динамическая память: `new`/`delete`, массивы `new[]`/`delete[]`; почему ручное управление опасно.
- [ ] `struct`, `enum`, `enum class`.
- [ ] Простые инварианты и проверка входных данных.

## Практика
- [ ] Реализуй консольную программу с меню и несколькими операциями.
- [ ] Реализуй обработку набора записей: добавление, вывод, поиск и изменение.
- [ ] Представь запись через `struct`, а ограниченный набор состояний — через `enum class`.
- [ ] Добавь обработку неверного пользовательского ввода.
- [ ] Разбей программу на функции с чёткой ответственностью.
- [ ] Найди и исправь утечки памяти и ошибки границ массивов в специально испорченной версии программы.

## Мини-проект: консольный менеджер заказов
Функции: создать заказ, вывести список, найти по идентификатору, изменить статус, рассчитать итоговую стоимость.

Ограничения:
- Используй только изученные средства.
- Не добавляй классы, шаблоны или сторонние библиотеки до соответствующих этапов.
- Не копируй готовую реализацию: сначала опиши структуру данных и интерфейс функций.

## Критерии перехода
- [ ] Умеешь самостоятельно написать программу из нескольких функций.
- [ ] Различаешь значение, ссылку и указатель.
- [ ] Понимаешь, где выделяется и освобождается динамическая память.
- [ ] Можешь объяснить назначение `struct`, `enum` и `enum class`.

- [ ] Перегрузка методов и `const`-методы.
- [ ] Статические поля и методы.

- [ ] `explicit`, конструкторы преобразования.
- [ ] Перегрузка операторов — только там, где смысл операции очевиден.
- [ ] `friend`: назначение и ограничения.
- [ ] Простые принципы проектирования: одна ответственность, минимальный публичный интерфейс.

## Практика
- [ ] Преврати запись заказа в класс с контролируемым изменением состояния.
- [ ] Запрети создание объекта в недопустимом состоянии.
- [ ] Добавь методы изменения статуса с проверкой допустимых переходов.
- [ ] Раздели интерфейс класса и реализацию по `.hpp` и `.cpp`.
- [ ] Напиши небольшой класс, который управляет ресурсом, и объясни, что произойдёт при выходе объекта из области видимости.

## Мини-проект: система учёта инвентаря
- [ ] Классы `Item`, `Inventory` и тип состояния или категории.
- [ ] Добавление, удаление, поиск и изменение количества.
- [ ] Инварианты: количество не отрицательное, идентификатор уникален.
- [ ] Внутренние данные нельзя менять в обход публичного интерфейса.

## Критерии перехода
- [ ] Можешь объяснить, почему поля не всегда следует делать публичными.
- [ ] Умеешь обеспечить инварианты объекта.
- [ ] Понимаешь порядок инициализации и уничтожения членов класса.
- [ ] Публичный интерфейс не раскрывает без необходимости детали реализации.

# Этап 3. Владение, время жизни и RAII

## Теория
- [ ] Время жизни объекта и область видимости.
- [ ] Автоматическая, статическая и динамическая длительность хранения.
- [ ] RAII: ресурс принадлежит объекту и освобождается в деструкторе.
- [ ] Проблемы сырых owning-указателей.
- [ ] Rule of Zero, Rule of Three и Rule of Five.
- [ ] Конструктор копирования и оператор копирующего присваивания.
- [ ] Конструктор перемещения и оператор перемещающего присваивания.
- [ ] Lvalue/rvalue на практическом уровне; `std::move` не перемещает сам по себе, а разрешает рассматривать объект как rvalue.
- [ ] `std::unique_ptr`, `std::shared_ptr`, `std::weak_ptr`.
- [ ] Уникальное и совместное владение; циклы `shared_ptr`.
- [ ] `std::vector`, `std::string` и другие RAII-контейнеры.
- [ ] Исключения: `try`, `catch`, `throw`, гарантия безопасности исключений.
- [ ] `noexcept` и его роль в перемещении и интерфейсах.
- [ ] Почему по умолчанию предпочтительнее стандартные контейнеры и умные указатели, а не ручные `new`/`delete`.

## Практика
- [ ] Реализуй тип-владелец простого ресурса и продумай копирование/перемещение.
- [ ] Сравни ручное управление ресурсом с RAII.
- [ ] Исправь утечку и двойное освобождение в демонстрационном коде.
- [ ] Применяй `std::unique_ptr` там, где владение должно быть единственным.
- [ ] Используй `std::vector` вместо динамического массива там, где ручное управление не требуется.
- [ ] Проверь поведение при исключении в середине операции.

## Мини-проект: безопасное хранилище файловых записей
- [ ] Храни записи в стандартных контейнерах.
- [ ] Определи владельца данных и правила передачи владения.
- [ ] Обеспечь корректное освобождение ресурсов при раннем выходе и ошибках.
- [ ] Не добавляй умные указатели только ради их использования: обоснуй модель владения.

## Критерии перехода
- [ ] Можешь объяснить RAII и Rule of Zero на примере.
- [ ] Умеешь определить, кто владеет ресурсом и сколько он живёт.
- [ ] Понимаешь различия между копированием и перемещением.
- [ ] Не используешь `new`/`delete` в обычном прикладном коде без обоснованной необходимости.

# Этап 4. Стандартная библиотека и идиоматичный C++

## Теория
- [ ] Контейнеры: `std::vector`, `std::array`, `std::deque`, `std::list` — характеристики и компромиссы.

- [ ] Итераторы и invalidation: когда операции делают итераторы/ссылки недействительными.
- [ ] Алгоритмы: `find`, `sort`, `count_if`, `transform`, `remove_if`, `accumulate`.
- [ ] Лямбда-выражения и захват переменных.
- [ ] `std::pair`, `std::tuple`, structured bindings.
- [ ] `std::optional`, `std::variant`, `std::string_view`, `std::span` (C++20).

- [ ] Потоки ввода-вывода и файловые потоки.
- [ ] `std::filesystem`.
- [ ] `std::format` — если поддерживается используемой стандартной библиотекой; альтернативы только при необходимости.
- [ ] Алгоритмы и контейнеры предпочтительнее самописных аналогов, если нет конкретной причины писать свои.

## Практика

- [ ] Для каждого используемого контейнера объясни выбор.
- [ ] Реализуй фильтрацию записей с лямбдой.
- [ ] Обработай отсутствие значения через `std::optional`, а альтернативные варианты состояния — через `std::variant`, если это уместно.
- [ ] Напиши утилиту, которая обходит каталог, фильтрует файлы и собирает статистику.

## Мини-проект: файловый индексатор
- [ ] Принимает путь к каталогу.
- [ ] Обходит файлы и собирает имя, размер и расширение.
- [ ] Поддерживает фильтрацию и сортировку.
- [ ] Корректно сообщает об ошибках доступа к файлам.
- [ ] Не загружает все содержимое файлов в память без необходимости.

## Критерии перехода
- [ ] Умеешь выбрать контейнер с учётом сложности операций и характера доступа.
- [ ] Используешь стандартные алгоритмы и понимаешь работу итераторов.
- [ ] Различаешь владеющую строку `std::string` и невладеющее представление `std::string_view`.
- [ ] Можешь объяснить риски времени жизни для `string_view` и `span`.

# Этап 6. Полиморфизм и архитектура

## Теория
- [ ] Наследование и композиция; предпочитай композицию, если отношение «является» не отражает модель.
- [ ] Виртуальные функции и динамический полиморфизм.
- [ ] Абстрактные классы и интерфейсы.
- [ ] Виртуальный деструктор и корректное уничтожение через базовый указатель.
- [ ] `override`, `final`.
- [ ] Срезка объектов (object slicing).
- [ ] Копирование полиморфных объектов и альтернативы.
- [ ] Зависимости между компонентами и инверсия зависимостей на практическом уровне.
- [ ] Разделение интерфейса и реализации.
- [ ] Минимально необходимые принципы SOLID; не применять их механически.

- [ ] Выдели интерфейс для нескольких реализаций одного поведения.

- [ ] Раздели систему на модули с чёткими зависимостями.
- [ ] Проверь, можно ли добавить новую реализацию без изменения несвязанных компонентов.

## Мини-проект: расширяемая система обработчиков
- [ ] Несколько обработчиков входных данных за общим интерфейсом.
- [ ] Выбор обработчика без переписывания основного сценария.
- [ ] Обоснованное владение объектами и корректное время жизни.

## Критерии перехода

- [ ] Понимаешь динамическое связывание и виртуальный деструктор.
- [ ] Можешь объяснить, откуда возникают зависимости между модулями.

# Этап 9. Linux и системное программирование

## Теория
- [ ] Процессы и потоки на уровне ОС.
- [ ] Файловые дескрипторы и стандартные потоки.
- [ ] Системные вызовы и отличие от библиотечных функций.
- [ ] `open`, `read`, `write`, `close`, `stat` и обработка ошибок через `errno`.
- [ ] Файловая система, права доступа, пути и каталоги.
- [ ] Процессы: `fork`, `exec`, `wait` — назначение и риски.
- [ ] Сигналы и безопасная обработка сигналов на базовом уровне.
- [ ] Переменные окружения, аргументы командной строки, exit codes.
- [ ] Виртуальная память, стек и куча, страницы памяти.
- [ ] Представление данных, выравнивание, endianness.
- [ ] Undefined behavior и его влияние на оптимизацию.
- [ ] Статические и динамические библиотеки, линковка, ABI.
- [ ] Основы `strace`, `ltrace`, `gdb`, `objdump`, `readelf`, `nm`.
- [ ] Основы `/proc` и системных метрик Linux.

## Практика
- [ ] Напиши CLI-утилиту, которая корректно обрабатывает пути и ошибки файловой системы.
- [ ] Реализуй копирование файла с обработкой частичных операций и ошибок системных вызовов.
- [ ] Исследуй поведение программы через `strace`.
- [ ] Сравни динамическую и статическую линковку на простом примере.
- [ ] Изучи память процесса и стек вызовов с помощью отладчика.
- [ ] Добавь обработку сигналов только там, где понимаешь ограничения безопасного кода в signal handler.

## Мини-проект: системная CLI-утилита
Выбери одну задачу: анализатор каталога, мониторинг размера файлов, поиск дубликатов по содержимому или диагностическая утилита для процессов.

Требования:
- [ ] Корректная обработка системных ошибок.
- [ ] Работа с большими каталогами без ненужного накопления всех данных в памяти.
- [ ] Логирование и тесты для ключевой логики.
- [ ] Документация ограничений и поведения при ошибках.

## Критерии перехода
- [ ] Различаешь библиотечные функции и системные вызовы.
- [ ] Умеешь анализировать базовые системные взаимодействия программы.
- [ ] Понимаешь процессы, виртуальную память, файловые дескрипторы и ABI на практическом уровне.

# Этап 10. Сетевое программирование

## Теория
- [ ] Модель клиент–сервер.
- [ ] TCP и UDP: гарантии, ограничения и случаи применения.
- [ ] IP-адреса, порты, DNS и базовая маршрутизация.
- [ ] Сокеты и системные интерфейсы POSIX.
- [ ] `bind`, `listen`, `accept`, `connect`, `send`, `recv`.
- [ ] Частичное чтение/запись и необходимость собственного протокола сообщений.
- [ ] Таймауты, отключения клиентов и обработка ошибок.
- [ ] Сериализация: форматы сообщений, длина, версии и валидация.
- [ ] Блокирующий и неблокирующий ввод-вывод.
- [ ] `select`, `poll`, основы `epoll`.
- [ ] Ограничения доверия к данным клиента и базовые принципы безопасной обработки входных данных.
- [ ] TLS и использование готовой проверенной библиотеки вместо самостоятельной реализации криптографии.

## Практика
- [ ] Напиши TCP-клиент и TCP-сервер для простого текстового протокола.
- [ ] Обработай отключение клиента, некорректные сообщения и частичное чтение.
- [ ] Добавь несколько одновременных клиентов.
- [ ] Определи формат сообщений и проверяй входные данные.
- [ ] Протестируй сценарии потери соединения и перезапуска сервера.

## Мини-проект: сетевой сервис
- [ ] Сервер принимает запросы и возвращает ответы по документированному протоколу.
- [ ] Есть ограничения размера сообщения и таймауты.
- [ ] Ошибки не приводят к падению всего сервиса.
- [ ] Есть логирование, тесты протокола и инструкция запуска клиента/сервера.

## Критерии перехода
- [ ] Понимаешь, почему TCP не сохраняет границы сообщений приложения.
- [ ] Обрабатываешь частичные операции и сетевые ошибки.
- [ ] Можешь объяснить компромиссы между блокирующим I/O и мультиплексированием.

# Этап 11. Многопоточность и конкурентность

## Теория
- [ ] `std::thread`, `std::jthread` (C++20), завершение и присоединение потоков.
- [ ] Data race, race condition, deadlock и starvation.
- [ ] `std::mutex`, `std::lock_guard`, `std::unique_lock`, `std::scoped_lock`.
- [ ] `std::condition_variable`.
- [ ] `std::atomic` и модель памяти на базовом уровне.
- [ ] `std::future`, `std::promise`, `std::async`.
- [ ] Очереди задач и thread pool — после уверенного понимания синхронизации.
- [ ] Передача владения и времени жизни данных между потоками.
- [ ] Синхронизация не должна заменять ясное проектирование владения.
- [ ] ThreadSanitizer и инструменты анализа конкурентного кода.

## Практика
- [ ] Распараллель вычислительную задачу и измерь результат относительно однопоточной версии.
- [ ] Реализуй потокобезопасную очередь с чётко описанными условиями блокировки.
- [ ] Найди и исправь гонку данных в специально подготовленном примере.
- [ ] Создай ограниченный пул рабочих потоков, если базовые задачи с mutex и condition variable уже понятны.
- [ ] Определи правила остановки и завершения всех потоков.

## Критерии перехода
- [ ] Можешь отличить data race от логической race condition.
- [ ] Понимаешь, какие данные защищает каждый mutex.
- [ ] Умеешь объяснить время жизни объектов, доступных нескольким потокам.
- [ ] Измеряешь ускорение и учитываешь накладные расходы.

# Этап 12. Производительность и углублённый C++

## Теория
- [ ] Сложность алгоритмов и стоимость операций контейнеров.
- [ ] Кэш-память, локальность данных и cache misses.
- [ ] Профилирование CPU и памяти.
- [ ] Аллокации, фрагментация и способы уменьшать ненужные выделения.
- [ ] Value semantics, копирование и перемещение в контексте производительности.
- [ ] Современные возможности C++17/20, необходимые проекту.
- [ ] Concepts, ranges и `std::span` — использование в подходящих интерфейсах.
- [ ] Coroutines — концепции и отдельное практическое изучение после освоения потоков и сетей.
- [ ] Atomics и memory ordering — углублять только при реальной необходимости.
- [ ] ABI, совместимость библиотек и стабильность публичных интерфейсов.
- [ ] Обработка ошибок: исключения, коды ошибок, `std::expected` (C++23, при наличии поддержки) и выбор по контракту API.
- [ ] Базовые принципы безопасного кода: границы, время жизни, отсутствие UB, минимизация доверенных участков.

## Практика
- [ ] Измерь несколько вариантов хранения и обработки одних данных.
- [ ] Сравни производительность до и после изменения, сохрани воспроизводимый бенчмарк.
- [ ] Профилируй реальную нагрузку и оптимизируй только обнаруженное узкое место.
- [ ] Проверь проект санитайзерами и статическим анализом.
- [ ] Документируй компромиссы между простотой, памятью и скоростью.

## Критерии перехода
- [ ] Не называешь код «быстрее» без измерений.
- [ ] Умеешь связать профиль с конкретным узким местом.
- [ ] Понимаешь основные причины лишних копирований, аллокаций и плохой локальности данных.

# Постоянные инструменты и привычки

## Инструменты
- [ ] Компилятор GCC или Clang.
- [ ] CMake.
- [ ] Git.
- [ ] GDB или LLDB.
- [ ] `clang-format`.
- [ ] `clang-tidy`.
- [ ] AddressSanitizer и UndefinedBehaviorSanitizer.
- [ ] ThreadSanitizer для подходящих многопоточных проектов.
- [ ] CTest и один тестовый фреймворк.
- [ ] `strace`, `readelf`, `objdump`, `nm` для системных задач.
- [ ] CI, например GitHub Actions или другой доступный сервис.

## Правила качества
- [ ] Включай предупреждения компилятора и не игнорируй их без причины.
- [ ] Не скрывай ошибки пустыми `catch` и не возвращай фиктивные значения вместо обработки ошибки.
- [ ] Не используй сырые owning-указатели без чёткой причины.
- [ ] Проверяй границы, время жизни и владение ресурсами.
- [ ] Не оптимизируй до измерения.
- [ ] Не добавляй абстракции, пока они не решают конкретную проблему.
- [ ] Для каждого исправленного дефекта по возможности добавляй тест.
- [ ] Записывай не только то, что сделал, но и почему выбрал именно это решение.
