# `struct`, `enum` и `enum class`

## `struct`
`struct` объединяет связанные данные в собственный тип.

```cpp
struct Product {
    int id;
    std::string name;
    int quantity;
    long long priceCents;
};

Product product{101, "Keyboard", 12, 250000};
```

У `struct` доступ по умолчанию `public`. В отличие от простого набора отдельных переменных, структура позволяет передавать связанную сущность целиком.

## Передача структуры в функцию
- `Product p` — копия;
- `const Product& p` — чтение без копирования;
- `Product& p` — можно менять оригинал;
- `Product* p` — работа через адрес; указатель может быть `nullptr`.

Выбирай форму передачи по назначению функции. Не передавай всё по неконстантной ссылке автоматически.

## `enum`
```cpp
enum Priority {
    Low,
    Medium,
    High
};
```
Обычный `enum` задаёт именованные целочисленные значения. Его имена могут попадать в окружающую область видимости, а значения могут неявно преобразовываться в целые числа.

## `enum class`
```cpp
enum class OrderStatus {
    New,
    Paid,
    Shipped,
    Cancelled
};
```
Использование: `OrderStatus::Paid`. Имена находятся в области перечисления, а значения не преобразуются автоматически в `int`. Это помогает избежать конфликтов имён и случайных преобразований.

## Использование в `switch`
```cpp
switch (status) {
case OrderStatus::New:
    // ...
    break;
case OrderStatus::Paid:
    // ...
    break;
case OrderStatus::Shipped:
    // ...
    break;
case OrderStatus::Cancelled:
    // ...
    break;
}
```

## Практические правила
- `struct` — для связанных полей одной сущности;
- `enum class` — для фиксированного набора состояний или категорий;
- проверяй пользовательский ввод до преобразования в перечисление;
- не храни известный набор статусов как произвольные строки без необходимости;
- не используй неинициализированные поля.

## Типичные ошибки
- смешивание несвязанных данных в одной структуре;
- использование неправильного значения перечисления;
- сравнение `enum class` с целым числом без явного преобразования;
- предположение, что числовые значения перечисления обязательно подходят для сохранения в файл или внешний протокол.
