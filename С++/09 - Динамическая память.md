# Динамическая память

## Автоматическая и динамическая память
Локальные автоматические объекты обычно живут до выхода из области видимости. Динамически выделенный объект живёт до освобождения или завершения программы. Его время жизни не привязано напрямую к блоку, где выделение произошло.

## `new` и `delete`
```cpp
int* ptr = new int{42};
delete ptr;
ptr = nullptr;
```
`new` создаёт один объект. `delete` освобождает объект, созданный соответствующим `new`.

## Динамический массив
```cpp
int size = 5;
int* values = new int[size]{};

// работа с values[0] ... values[size - 1]

delete[] values;
values = nullptr;
```
Для `new[]` используется `delete[]`. Для одиночного `new` используется `delete`.

## Основные риски
- **утечка памяти:** адрес потерян до освобождения;
- **двойное освобождение:** один ресурс освобождён дважды;
- **use-after-free:** обращение после освобождения;
- **out-of-bounds:** доступ за границы выделенного массива;
- **необработанная ошибка выделения:** `new` обычно выбрасывает `std::bad_alloc`, если не используется специальная форма.

## Правила безопасной работы
1. Определи владельца каждого выделенного ресурса.
2. Каждому успешному выделению должен соответствовать правильный способ освобождения.
3. Не копируй владеющий сырой указатель как будто это независимый ресурс.
4. Не освобождай память, которой не владеешь.
5. Не используй указатель после `delete`/`delete[]`.
6. При ошибке или раннем выходе не забывай об освобождении.
7. В реальном современном коде предпочитай RAII-контейнеры и умные указатели.

## `nullptr`
После освобождения указатель можно обнулить, чтобы уменьшить риск случайного повторного использования. Это не исправляет другие копии того же адреса и не заменяет управление временем жизни.

## `int**`
`int**` — указатель на указатель. Его можно использовать для массива указателей или таблицы, где строки выделены отдельно, но такая структура не обязательно непрерывна в памяти. Освобождать её нужно по уровням в соответствии со способом выделения.

## Частые ошибки
- `delete` вместо `delete[]`;
- `delete[]` вместо `delete`;
- отсутствие освобождения;
- разыменование после освобождения;
- возврат адреса локальной переменной;
- копирование владельца без глубокого копирования или безопасной модели владения.
