# Компиляция, линковка и модель программы

## Этапы сборки

1. **Препроцессор** обрабатывает директивы `#include`, `#define`, условную компиляцию.
2. **Компилятор** анализирует C++ и переводит единицу трансляции в объектный код.
3. **Ассемблер** формирует объектный файл (`.o`/`.obj`).
4. **Линковщик** объединяет объектные файлы и библиотеки, разрешает внешние символы.
5. Результат — исполняемый файл или библиотека.

## Типы ошибок

- **Компиляция:** синтаксис, типы, недопустимые операции.
- **Линковка:** отсутствующее определение функции/переменной, несколько конфликтующих определений.
- **Выполнение:** неверные данные, ошибка файла, аварийное завершение.
- **Логическая ошибка:** программа запускается, но результат неверен.
- **Undefined behavior (UB):** стандарт не определяет поведение; компилятор вправе оптимизировать исходя из предположения, что UB не происходит.

## Единицы трансляции

Каждый `.cpp` после обработки `#include` компилируется как отдельная единица трансляции. Заголовки обычно содержат объявления, которые включаются в несколько единиц трансляции.

```cpp
// math.hpp
#pragma once
int add(int a, int b);

// math.cpp
#include "math.hpp"
int add(int a, int b) { return a + b; }

// main.cpp
#include "math.hpp"
int main() { return add(2, 3) == 5 ? 0 : 1; }
```

## ODR — One Definition Rule

- Сущность обычно должна иметь одно допустимое определение в программе.
- Не помещай обычные определения не-inline функций и глобальных переменных в заголовок, включаемый несколькими `.cpp`.
- Функции, определённые внутри класса, обычно неявно `inline`.
- Шаблонные определения обычно размещают в заголовках, чтобы компилятор видел их при инстанцировании.

## Полезные параметры GCC/Clang

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -Wconversion -Wshadow \
    -g main.cpp math.cpp -o app
```

- `-std=c++20` — версия стандарта.
- `-Wall -Wextra -Wpedantic` — дополнительные предупреждения.
- `-g` — отладочная информация.
- `-O0` — минимизация оптимизаций для отладки; `-O2` — оптимизация.
- `-fsanitize=address,undefined` — обнаружение части ошибок памяти и UB при запуске.

## Типичные ошибки

- Считать, что `#include` — это компоновка: фактически препроцессор вставляет содержимое заголовка.
- Определить одну обычную функцию в заголовке и получить multiple definition.
- Исправлять linker error как синтаксическую ошибку.
- Игнорировать предупреждения компилятора.

## Практика

- Собери программу из двух `.cpp` и одного заголовка.
- Создай и исправь ошибку компиляции, линковки и выполнения.
- Собери программу с предупреждениями и объясни каждое предупреждение.
