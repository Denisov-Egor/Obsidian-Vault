# Сериализация и форматы бинарных протоколов

## Сериализация

Сериализация преобразует структуру данных в определённое представление для хранения или передачи. Десериализация восстанавливает данные и обязана проверять корректность входа.

## Не записывай объект напрямую в файл как универсальный формат

`write(reinterpret_cast<const char*>(&object), sizeof(object))` не создаёт переносимый формат, потому что:
- в объекте могут быть padding bytes;
- layout зависит от ABI и платформы;
- указатели не сохраняют смысл между процессами;
- порядок байтов может отличаться;
- версии структуры могут не совпадать;
- не все типы имеют подходящее представление для такого хранения.

## Проектирование формата

Определи:
- magic bytes / сигнатуру формата;
- версию;
- тип сообщения;
- длину сообщения;
- порядок байтов;
- кодировку строк;
- ограничения количества элементов и длины полей;
- поведение при неизвестной версии и лишних полях;
- контроль целостности, если это требуется моделью угроз.

## Безопасная десериализация

- Проверяй длину до чтения и выделения памяти.
- Не доверяй числам длины из входного сообщения.
- Проверяй переполнение при вычислении смещений.
- Учитывай неполное сообщение и лишние байты.
- Не интерпретируй произвольные входные байты как валидный C++-объект.
- Разделяй разбор формата и применение бизнес-логики.

## Текстовый и бинарный формат

- Текстовый формат удобнее для отладки, но может быть больше.
- Бинарный формат компактнее, но требует строгого описания представления.
- Выбирай формат по требованиям; не изобретай бинарный протокол без необходимости.

## Практика

- Опиши формат записи с версией и длиной.
- Реализуй чтение с проверкой границ и обработкой повреждённого файла.
- Добавь тесты для пустого, обрезанного и некорректного сообщения.
