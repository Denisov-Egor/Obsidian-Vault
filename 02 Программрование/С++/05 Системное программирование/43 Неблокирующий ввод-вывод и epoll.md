# Неблокирующий ввод-вывод и `epoll`

## Блокирующий и неблокирующий I/O

- Блокирующий вызов ждёт, пока операция сможет продвинуться или завершиться.
- Неблокирующий вызов возвращается, если операция сейчас не может продолжиться.
- `EAGAIN`/`EWOULDBLOCK` обычно означает, что нужно дождаться следующей возможности.
- `EINTR` означает, что вызов был прерван сигналом; обработка зависит от операции.
- Даже при успешном вызове `read`, `write`, `send` или `recv` может обработать меньше байтов, чем запрошено.

## Мультиплексирование

- `select` — старый механизм ожидания готовности набора дескрипторов с ограничениями по размеру набора.
- `poll` — массив дескрипторов, без ограничения `fd_set`, но при проверке обычно сканируется массив.
- `epoll` — Linux API для наблюдения за готовностью большого числа дескрипторов.

## Модель работы с epoll

1. Создать экземпляр через `epoll_create1`.
2. Зарегистрировать дескриптор через `epoll_ctl`.
3. Ожидать события через `epoll_wait`.
4. При событии выполнять чтение/запись до `EAGAIN` для edge-triggered режима.
5. При закрытии клиента удалить состояние соединения и закрыть дескриптор.

## Level-triggered и edge-triggered

- **Level-triggered:** событие продолжает сообщаться, пока условие готовности сохраняется.
- **Edge-triggered (`EPOLLET`):** сообщается изменение состояния; обычно нужно читать/писать до `EAGAIN`, иначе можно пропустить дальнейшую обработку доступных данных.
- Неблокирующий режим особенно важен для edge-triggered модели.

## Состояние соединения

Для каждого клиента храни:
- входной буфер;
- выходной буфер;
- состояние парсера протокола;
- ограничения размера сообщения;
- таймауты и состояние закрытия;
- ошибки и статистику.

TCP — поток байтов, а не очередь сообщений. Протокол должен задавать границы сообщений, например длиной в заголовке.

## Практика

- Реализуй сервер, обслуживающий несколько клиентов через `poll`.
- Добавь очередь исходящих данных и обработку частичных отправок.
- Перенеси сервер на `epoll`, сравни сложность и измерь поведение под нагрузкой.
