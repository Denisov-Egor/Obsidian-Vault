# 22 Отладка, тестирование и качество

## Цели
- [ ] Диагностировать дефекты и проверять поведение.
- [ ] Автоматизировать проверки.

## Теория
- Сначала воспроизвести дефект и сформулировать гипотезу. GDB: breakpoints, шаги, стек вызовов, переменные. Unit-тест проверяет отдельное поведение. Граничные случаи: пустой ввод, один элемент, лимиты, дубликаты, неверный формат. ASan выявляет ряд ошибок памяти, UBSan — ряд случаев UB. Логику отделять от ввода/вывода.

## Типичные ошибки
- Менять код без диагноза
- тестировать только успех
- зависимость теста от порядка
- игнорировать предупреждения.

## Практика
- [ ] Тесты банковских операций
- [ ] тесты повреждённого файла
- [ ] найти ошибку через GDB.

## Критерии завершения
- [ ] Могу объяснить ключевые понятия своими словами.
- [ ] Решаю практическую задачу без готового решения.
- [ ] Проверяю граничные случаи и ошибки.
