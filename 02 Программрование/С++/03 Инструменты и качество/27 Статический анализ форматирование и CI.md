# Статический анализ, форматирование и CI

## Инструменты

- **Compiler warnings:** находят часть подозрительных конструкций во время компиляции.
- **clang-format:** единообразное форматирование.
- **clang-tidy:** статические проверки и рекомендации по исправлению.
- **Sanitizers:** обнаружение отдельных классов ошибок во время выполнения.
- **Unit tests:** проверка небольших компонентов.
- **Integration tests:** проверка взаимодействия компонентов.
- **CI (Continuous Integration):** автоматическая сборка и проверки при изменении репозитория.

## Минимальный локальный цикл

1. Собрать Debug-версию с предупреждениями.
2. Запустить тесты.
3. Запустить санитайзеры на тестовом наборе.
4. Проверить форматирование.
5. Просмотреть `git diff`.
6. Зафиксировать изменение отдельным коммитом.

## Пример проверок

```bash
clang-format --dry-run --Werror src/*.cpp include/*.hpp
clang-tidy src/*.cpp -- -std=c++20
ctest --test-dir build --output-on-failure
```

Конкретные аргументы зависят от структуры проекта и версии инструментов.

## CI должен

- установить нужные инструменты;
- настроить сборку;
- собрать проект с предупреждениями;
- запустить тесты;
- при необходимости запускать sanitizers и статический анализ;
- сообщить об ошибке до слияния изменений.

## Практика

- Добавь форматирование и тесты в существующий проект.
- Настрой CI для Linux, который конфигурирует CMake, собирает проект и запускает CTest.
- Убедись, что намеренно сломанный тест делает CI неуспешным.
