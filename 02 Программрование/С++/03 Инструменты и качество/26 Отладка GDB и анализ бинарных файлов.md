# Отладка GDB и анализ бинарных файлов

## Сборка для отладки

```bash
g++ -std=c++20 -Wall -Wextra -Wpedantic -g -O0 main.cpp -o app
gdb ./app
```

## Базовые команды GDB

- `break main` — точка останова.
- `break file.cpp:42` — остановка на строке.
- `run` — запуск.
- `next` — следующая строка без входа в функцию.
- `step` — войти в функцию.
- `finish` — выполнить до выхода из текущей функции.
- `print variable` — значение выражения.
- `display variable` — показывать выражение после остановок.
- `backtrace` / `bt` — стек вызовов.
- `frame N` — выбрать кадр стека.
- `watch variable` — остановка при изменении значения.
- `continue` — продолжить выполнение.
- `quit` — завершить GDB.

## Методика поиска дефекта

1. Воспроизведи ошибку минимальным примером.
2. Зафиксируй ожидаемый и фактический результат.
3. Найди первый момент, где состояние отличается от ожидаемого.
4. Проверь входные данные, границы, время жизни и инварианты.
5. Исправь причину, а не симптом.
6. Добавь тест, который падает до исправления и проходит после него.

## Анализ бинарных файлов

- `file ./app` — тип файла и архитектура.
- `ldd ./app` — динамические зависимости для доверенного локального бинарника.
- `readelf -h ./app` — заголовок ELF.
- `readelf -d ./app` — динамический раздел.
- `nm -C ./app` — символы с деманглингом C++.
- `objdump -d ./app` — дизассемблирование.
- `strace ./app` — системные вызовы процесса.
- `ltrace ./app` — вызовы библиотечных функций там, где инструмент поддерживает их отслеживание.

## Санитайзеры

```bash
g++ -std=c++20 -g -O1 -fsanitize=address,undefined \
    -fno-omit-frame-pointer main.cpp -o app
```

AddressSanitizer выявляет многие ошибки памяти, UndefinedBehaviorSanitizer — часть случаев UB. Это не доказательство отсутствия ошибок.

## Практика

- Найди источник неверного значения с помощью breakpoint и watchpoint.
- Изучи стек вызовов при аварийном завершении.
- Сравни вывод `file`, `readelf` и `nm` для исполняемого файла.
