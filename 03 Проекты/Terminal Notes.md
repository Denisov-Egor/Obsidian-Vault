# Terminal Notes — C++ Project

> [!abstract] О проекте  
> **Terminal Notes** — консольный менеджер заметок для Linux, написанный на C++.
> 
> Цель проекта — создать полезную программу, одновременно закрепляя знания C++ на практике.
> 
> **Версия:** v0.1  
> **Стандарт:** C++20  
> **Платформа:** Linux  
> **Интерфейс:** терминал  
> **Хранение данных:** оперативная память  
> **Лимит:** 100 заметок

---

# 1. Цель проекта

Создать консольное приложение, позволяющее пользователю:

- создавать заметки;
    
- просматривать список заметок;
    
- открывать конкретную заметку;
    
- работать с несколькими заметками в рамках одного запуска программы.
    

Проект должен развиваться постепенно. Новые возможности добавляются только после изучения необходимых для них возможностей C++.

## Главные принципы

1. Не добавлять функции ради количества.
    
2. Каждая функция и каждый класс должны иметь конкретную ответственность.
    
3. Не дублировать логику без необходимости.
    
4. Не использовать непройденные возможности C++ без предварительного изучения.
    
5. Писать понятный и поддерживаемый код.
    
6. Проверять каждую часть программы отдельно.
    
7. Проект должен запускаться непосредственно из Linux-терминала.

# 2. Функциональность v0.1

## 2.1. Создание заметок

Пользователь может создавать новые заметки.

Каждая заметка содержит:

|Поле|Тип|Назначение|
|---|---|---|
|title|std::string|Заголовок|
|content|std::string|Текст заметки|

Пример:

```
Заголовок: Изучение C++

Содержимое:
Сегодня изучаю классы и инкапсуляцию.
```

Требования:

- Можно создать несколько заметок.
    
- Новая заметка не должна изменять существующие.
    
- Максимальное количество заметок — 100.
    
- При достижении лимита программа сообщает об ошибке.
    
- Пустые строки пока не запрещаются.
    

## 2.2. Просмотр списка заметок

Программа должна показывать все созданные заметки.

Пример:

```
========== NOTES ==========

1. Изучение C++
2. Настройка Arch Linux
3. Идеи проектов
4. Изучение Rust

===========================
```

Требования:

- Каждая заметка получает порядковый номер.
    
- Показываются заголовки.
    
- Если заметок нет, выводится понятное сообщение.
    

## 2.3. Открытие заметки

Пользователь выбирает заметку по номеру.

Пример:

```
========== NOTE ==========

Номер: 1
Заголовок: Изучение C++

Содержимое:
Сегодня изучаю классы и инкапсуляцию.

==========================
```

Требования:

- Пользователь вводит порядковый номер.
    
- Программа проверяет корректность номера.
    
- При неправильном номере выводится сообщение об ошибке.
    
- После ошибки программа возвращается в главное меню.
    

## 2.4. Выход

При выборе выхода программа завершает работу.

Все заметки хранятся только в оперативной памяти. После завершения программы они исчезают.

# 3. Архитектура проекта

Приложение разделяется на три основных компонента.

|Компонент|Ответственность|
|---|---|
|Note|Представляет одну заметку|
|NoteManager|Управляет коллекцией заметок|
|ConsoleUI|Отвечает за взаимодействие с пользователем|

Дополнительно `main.cpp` будет содержать точку входа в программу.

## 3.1. Общая схема

```
             Terminal Notes
                    |
                    v
                main.cpp
                    |
                    v
                ConsoleUI
                    |
                    v
                NoteManager
                    |
                    v
                  Note
```

### Note

Отвечает за одну заметку.

Не должен:

- показывать главное меню;
    
- управлять другими заметками;
    
- самостоятельно взаимодействовать с терминалом;
    
- хранить всю коллекцию.
    

### NoteManager

Отвечает за коллекцию заметок.

Не должен:

- самостоятельно рисовать пользовательский интерфейс;
    
- заниматься оформлением сообщений;
    
- управлять главным циклом программы.
    

### ConsoleUI

Отвечает за взаимодействие с пользователем.

Не должен:

- самостоятельно хранить коллекцию заметок;
    
- напрямую изменять приватные поля объектов;
    
- дублировать логику управления коллекцией.

# 5. Класс Note

## Назначение

Представляет одну заметку и управляет её данными.

## Приватные поля

|Поле|Тип|Назначение|
|---|---|---|
|title|std::string|Заголовок|
|content|std::string|Содержимое|

Оба поля должны находиться в `private`.

## Публичные методы

|Метод|Назначение|
|---|---|
|setTitle()|Изменяет заголовок|
|setContent()|Изменяет содержимое|
|getTitle()|Возвращает заголовок|
|getContent()|Возвращает содержимое|

## Предполагаемый интерфейс

```
class Note
{
private:
    std::string title;
    std::string content;

public:
    void setTitle(const std::string& newTitle);
    void setContent(const std::string& newContent);

    std::string getTitle() const;
    std::string getContent() const;
};
```

Это целевая форма интерфейса, а не готовая реализация. Методы предстоит написать самостоятельно.

# 6. Класс NoteManager

## Назначение

Управляет всеми заметками приложения.

## Принцип хранения

Используется фиксированный массив:

- максимальное количество — 100 объектов `Note`;
    
- отдельная переменная хранит текущее количество заметок;
    
- новые заметки добавляются в свободную позицию.
    

Пока не используем `std::vector` и динамические контейнеры.

## Предполагаемые методы

|Метод|Назначение|
|---|---|
|addNote()|Добавляет новую заметку|
|getNoteCount()|Возвращает количество заметок|
|getNote()|Получает заметку по индексу|
|showAllNotes()|Показывает список заметок|
|isEmpty()|Проверяет, пуста ли коллекция|
|isFull()|Проверяет, достигнут ли лимит|

> [!note] Архитектурное решение  
> Список методов предварительный. После проектирования проверим, какие методы действительно необходимы, какие лучше объединить, а какие должны находиться в другом компоненте.

# 11. Сборка и запуск

После создания всех файлов сборка будет выполняться через терминал.

Предполагаемая команда:

```
g++ -std=c++20 -Wall -Wextra -Wpedantic \
    -Iinclude \
    main.cpp \
    src/Note.cpp \
    src/NoteManager.cpp \
    src/ConsoleUI.cpp \
    -o terminal-notes
```

Запуск:

```
./terminal-notes
```

CMake пока не используем. Изучим его отдельно, когда появится необходимость.
